# Active Liveness 디자인 고도화 요청 항목

이 문서는 현재 Active Liveness UI/UX 프로토타입을 실제 프로덕트 디자인으로 고도화하기 위해 디자이너가 검토해야 할 항목을 정리한 문서다.

프로덕트 버전의 목표는 사용자가 기술 지표를 이해하지 않아도, 화면 안내만 따라 자연스럽게 얼굴 라이브니스 인증을 완료할 수 있게 만드는 것이다.

## 1. 프로덕트 화면에 남길 요소

실제 사용자 화면에는 다음 요소만 노출한다.

| 요소 | 설명 |
| --- | --- |
| 카메라 프리뷰 | 사용자의 얼굴과 주변 환경이 보이는 영역 |
| 얼굴 가이드 | 얼굴을 맞출 원형 가이드. 기본 흰색, 진행 중 라임색, 오류 시 일정 조건에서만 빨간색 |
| 단계 안내 문구 | 현재 사용자가 해야 할 행동을 짧고 명확하게 안내 |
| 단계 진행 바 | 현재 단계에서 조건을 유지한 시간의 진행도. 각 단계마다 0~100으로 리셋 |
| 스낵바 | 조명, 거리, 얼굴 위치, 가림 등 사용자가 고칠 수 있는 문제를 일정 시간 지속 시 안내 |
| 다시 시작하기 버튼 | 실패, 중단, 완료 후 플로우를 처음부터 다시 시작 |
| 완료 화면 | PASS 이후 인증 완료 상태를 명확히 전달 |

## 2. 프로덕트 화면에서 제거할 요소

현재 프로토타입에 있는 다음 요소는 실제 프로덕트 UI에 노출하지 않는다.

| 요소 | 처리 방향 |
| --- | --- |
| Mesh 토글 | 프로덕트 화면에서는 제거. 개발/QA 디버그 모드에서만 사용 |
| Contours 토글 | 프로덕트 화면에서는 제거. 개발/QA 디버그 모드에서만 사용 |
| Key points 토글 | 프로덕트 화면에서는 제거. 개발/QA 디버그 모드에서만 사용 |
| Vectors 토글 | 프로덕트 화면에서는 제거. 개발/QA 디버그 모드에서만 사용 |
| 품질 점수 | 프로덕트 화면에서는 제거. 사용자에게 숫자로 노출하지 않음 |
| yaw, pitch, EAR, jitter 등 세부 지표 | 프로덕트 화면에서는 제거 |
| 남은 스텝/분석 패널 | 프로덕트 화면에서는 제거 |
| Detail 버튼 | 프로덕트 화면에서는 제거. 필요 시 내부 QA 빌드에서만 활성화 |
| 초기화 버튼 | 제거. 사용자에게는 `다시 시작하기`만 제공 |

## 3. 인증 플로우

프로덕트 플로우는 다음 순서로 디자인한다.

1. 시작 화면
2. 카메라 권한 요청/카메라 준비
3. 정면 맞추기 + 눈 깜빡임
4. 오른쪽으로 50~60도 돌리기
5. 왼쪽으로 50~60도 돌리기
6. 고개 숙이기
7. 고개 들기
8. PASS 완료

각 단계는 연속적으로 진행되지만, 단계가 전환될 때 사용자가 갑자기 화면이 바뀌었다고 느끼지 않도록 1~2초 정도의 시각적 여유가 필요하다.

## 4. 화면별 디자인 필요 항목

### 4.1 시작 화면

디자인 필요 항목:

- 서비스/기능명을 보여주는 첫 진입 화면
- `모바일 신분증으로 계속하기` 또는 실제 서비스 플로우에 맞는 시작 CTA
- 어두운 배경에서도 브랜드 식별이 가능한 로고/워드마크 영역
- 모바일 세로 화면 기준의 안정적인 하단 버튼 배치

검토 포인트:

- 이 화면이 실제 서비스 내 모달인지, 전체 화면인지 결정 필요
- Face ID 등록이라는 표현을 그대로 쓸지, 신분증/본인확인 맥락의 표현으로 바꿀지 결정 필요

### 4.2 카메라 준비/권한 화면

디자인 필요 항목:

- 카메라 권한 요청 전 상태
- 권한 허용 후 카메라 로딩 상태
- 권한 거부 상태
- 카메라 접근 실패 상태
- iOS Safari에서 카메라가 끊겼을 때 재시도 안내

검토 포인트:

- 권한 거부 시 브라우저 설정에서 카메라 권한을 다시 켜는 안내가 필요함
- 네트워크/모델 로딩 실패와 카메라 권한 실패를 같은 오류로 보여주면 안 됨

### 4.3 카메라 인증 화면

디자인 필요 항목:

- 큰 원형 얼굴 가이드
- 원 바깥 영역 딤드 처리
- 얼굴 가이드 안쪽 카메라 화면 가독성
- 단계 안내 문구
- 단계별 진행 바
- 다시 시작하기 버튼
- 상단 타이틀/뒤로가기 영역

현재 프로토타입 기준:

- 얼굴 가이드는 원형
- 바깥 딤드는 `#000000`, alpha `0.3`
- 가이드 기본 색상은 흰색
- 현재 단계 조건을 만족해 진행 바가 차기 시작하면 라임 계열
- 오류 상태는 빨간색 계열

검토 포인트:

- 실제 얼굴이 가이드 안에 들어왔을 때 얼굴이 너무 작아 보이지 않는 원 크기
- iPhone SE급 작은 화면에서도 버튼과 안내 문구가 겹치지 않는 레이아웃
- 카메라 화면이 거울처럼 보이는 전면 카메라 UX 유지

### 4.4 단계 안내 문구

현재 기능 기준으로 다음 문구를 디자인 기준 문구로 검토한다.

| 단계 | 기본 안내 문구 |
| --- | --- |
| 정면 + 눈 깜빡임 | 얼굴을 원 안에 맞추고 눈을 깜빡여주세요 |
| 오른쪽 회전 | 얼굴을 오른쪽으로 50~60도 정도 돌려주세요 |
| 왼쪽 회전 | 얼굴을 왼쪽으로 50~60도 정도 돌려주세요 |
| 고개 숙이기 | 고개를 아래로 살짝 숙여주세요 |
| 고개 들기 | 고개를 위로 살짝 들어주세요 |
| 완료 | 좋아요! |

디자인 필요 항목:

- 단계 문구가 바뀔 때 이전 문구가 위로 페이드아웃되고 다음 문구가 자연스럽게 등장하는 전환
- 통과 직후 긍정 피드백 문구
- 다음 단계 진입 전 짧은 대기 상태
- 긴 문구가 작은 모바일 화면에서 두 줄로 안전하게 떨어지는 규칙

검토 포인트:

- `천천히 돌려주세요`보다 `50~60도 정도 돌려주세요`가 사용자의 오해를 줄일 가능성이 높음
- 방향 안내는 사용자가 보는 거울 화면 기준으로 이해되어야 함

### 4.5 진행 바

디자인 필요 항목:

- 각 단계별 0~100 진행 바
- 다음 단계로 넘어갈 때 진행 바가 0으로 리셋되는 전환
- 조건을 잃었을 때 진행 바가 급격히 튀지 않는 감소/리셋 표현
- 성공 시 라임/긍정 색상으로 완료 상태 표시

검토 포인트:

- 진행 바는 전체 플로우 진행률이 아니라 현재 단계 유지 시간의 진행률임
- 사용자가 "조금만 더 유지하면 된다"는 느낌을 받을 수 있어야 함

### 4.6 스낵바/오류 안내

스낵바는 너무 자주 나타나면 인증 중인 사용자를 방해한다. 따라서 문제 상태가 일정 시간 지속될 때만 노출하는 UX를 기준으로 한다.

디자인 필요 항목:

- 스낵바 기본 위치
- 스낵바 등장/퇴장 모션
- 오류 아이콘/텍스트 스타일
- 빨간 얼굴 가이드와 스낵바의 동시 노출 상태
- 문제가 해소되었을 때 즉시 사라지는 상태

스낵바 예시 문구:

| 상황 | 안내 문구 |
| --- | --- |
| 얼굴 미감지 | 얼굴을 카메라 안에 맞춰주세요 |
| 여러 얼굴 감지 | 한 명만 화면에 들어와 주세요 |
| 너무 어두움 | 어두운 환경에서는 얼굴 인식이 어려워요 |
| 너무 밝음/역광 | 얼굴이 잘 보이도록 밝기를 조정해 주세요 |
| 얼굴이 너무 작음 | 카메라에 조금 더 가까이 와 주세요 |
| 얼굴이 너무 큼 | 카메라에서 조금만 멀어져 주세요 |
| 얼굴 위치 벗어남 | 얼굴을 원 안에 맞춰주세요 |
| 눈/코/입 가림 의심 | 눈, 코, 입이 잘 보이게 해주세요 |
| 카메라 중단 | 카메라 연결이 끊겼어요. 다시 시도해 주세요 |

검토 포인트:

- 스낵바 문구는 사용자를 탓하는 느낌이 없어야 함
- 실패 사유는 기술 지표가 아니라 사용자가 바로 고칠 수 있는 행동으로 표현해야 함
- 스낵바와 빨간 테두리는 문제 상태가 약 1.5초 지속될 때 표시하는 것을 기준으로 함
- 빨간 테두리는 즉시 경고가 아니라, 지속적인 문제 상태에서만 나타나는 보조 피드백이어야 함

### 4.7 완료/PASS 화면

디자인 필요 항목:

- 인증 완료 상태
- 다음 서비스 플로우로 이동하는 CTA
- 다시 시작하기 버튼이 필요한 경우의 위치
- 완료 직후 카메라 프리뷰를 유지할지, 완료 전용 화면으로 전환할지 결정

검토 포인트:

- PASS 상태는 사용자가 명확하게 인증이 끝났다고 인지해야 함
- 실제 서비스에서는 완료 후 자동 이동이 필요한지, 명시적 버튼이 필요한지 결정 필요

## 5. 버튼 정책

프로덕트 화면의 버튼은 최소화한다.

| 버튼 | 노출 여부 | 설명 |
| --- | --- | --- |
| 다시 시작하기 | 노출 | 인증 플로우를 처음부터 다시 시작 |
| 초기화 | 제거 | 프로토타입/개발용 기능이므로 사용자 화면에서 제거 |
| Detail | 제거 | 개발/QA 전용 |
| Mesh/Contours/Key points/Vectors | 제거 | 개발/QA 전용 |

검토 포인트:

- `다시 시작하기`는 인증 중에도 항상 보일지, 오류/완료 상태에서만 보일지 결정 필요
- 실수 터치를 막기 위해 위치와 시각적 위계를 조정해야 함

## 6. 모바일 반응형 기준

우선 디자인 기준은 모바일 웹이다.

디자인 필요 항목:

- iPhone SE급 작은 세로 화면
- 일반 iPhone 세로 화면
- 큰 Android 세로 화면
- 태블릿 세로/가로 화면
- PC 브라우저에서의 미리보기/QA 화면

검토 포인트:

- 카메라 화면, 원형 가이드, 문구, 진행 바, 버튼이 어떤 화면에서도 겹치지 않아야 함
- 하단 버튼은 Safari 주소창/홈 인디케이터 영역을 고려해야 함
- PC에서는 실제 프로덕트 화면과 QA 확인 화면의 용도를 분리할지 결정 필요

## 7. 모션/인터랙션 기준

디자인 필요 항목:

- 단계 전환 모션
- 안내 문구 페이드/슬라이드 전환
- 진행 바 증가 모션
- 스낵바 등장/퇴장 모션
- PASS 완료 피드백 모션
- 카메라 로딩 상태 모션

검토 포인트:

- 인증 중 모션은 화려함보다 안정감이 중요함
- 사용자가 얼굴을 움직이는 중이므로 화면 요소가 과하게 움직이면 안 됨
- 오류 상태는 강하게 흔들기보다 조용히 알려주는 편이 적합함

## 8. 색상/시각 상태

디자인 필요 항목:

- 기본 상태 색상
- 진행 중 상태 색상
- 완료 상태 색상
- 오류 상태 색상
- 딤드 색상
- 스낵바 배경/텍스트/아이콘 색상

현재 프로토타입 기준:

| 상태 | 방향 |
| --- | --- |
| 기본 | 흰색 |
| 진행 중/성공 | 라임 계열 |
| 오류 | 레드 계열 |
| 외곽 딤드 | `#000000`, alpha `0.3` |
| 배경 | 카메라 프리뷰 위주 |

검토 포인트:

- 라임색은 브랜드 포인트로 유지할지 확인 필요
- 오류 레드는 너무 공격적으로 보이지 않게 조정 필요
- 카메라 영상 위에서도 충분한 대비가 필요함

## 9. 접근성/사용성

디자인 필요 항목:

- 색상만으로 성공/오류를 구분하지 않는 보조 텍스트
- 작은 화면에서 읽히는 최소 글자 크기
- 버튼 터치 영역 최소 크기
- 스낵바 노출 시간이 너무 짧지 않도록 기준 설정
- 모션 감소 설정 사용자를 위한 과도한 애니메이션 제한

검토 포인트:

- 사용자는 인증 중 화면을 오래 읽기 어렵기 때문에 문구는 짧아야 함
- 시력이 낮은 사용자도 진행 상태와 오류 상태를 구분할 수 있어야 함

## 10. 디자인 산출물 요청 목록

디자이너에게 요청할 산출물은 다음과 같다.

| 산출물 | 포함 내용 |
| --- | --- |
| 모바일 메인 플로우 화면 | 시작, 권한, 인증 진행, 완료 |
| 단계별 인증 화면 | 정면+깜빡임, 오른쪽, 왼쪽, 숙이기, 들기 |

## 11. 디자이너 검토 질문

- `다시 시작하기` 버튼은 인증 중 항상 노출할 것인가, 문제 발생/완료 상태에서만 노출할 것인가?

- 개발/QA용 디버그 화면은 별도 URL 또는 숨겨진 모드로 유지할 것인가?
